# Регламент командной разработки и внесения изменений (CONTRIBUTING)

Данный документ определяет правила совместной работы команды над проектом «Интернет-магазин комплектующих для ПК», организацию веток в Git, стандарты коммитов и процедуру рецензирования изменений (Code / Docs Review).

---

## 1. Ветвление репозитория

- **Основная ветка (`main`):**
  Содержит только стабильные, проверенные и согласованные всей командой материалы (отчеты, диаграммы, спецификации, исходный код).
  Прямые коммиты в ветку `main` запрещены.
  
- **Тематические ветки (Feature / Docs Branches):**
  Любая работа выполняется в отдельной ветке, ответвляемой от актуального состояния `main`.
  Формат именования веток:
  - `docs/uc-<номер>` — работа над документацией по конкретному сценарию (например, `docs/uc-05-cart`, `docs/uc-06-order`);
  - `docs/pz-<номер>` — оформление материалов к соответствующему практическому занятию (например, `docs/pz-3-diagrams`, `docs/pz-4-repo`);
  - `feature/<название>` — разработка программного модуля или компонента;
  - `fix/<описание>` — исправление ошибок или замечаний рецензирования.

---

## 2. Соглашения по коммитам (Commit Messages)

Сообщения коммитов должны быть осмысленными и отражать суть внесенных изменений на русском или английском языке:

- `docs: добавлен сценарий и PlantUML диаграмма UC-06 Оформление заказа`
- `docs: актуализирована таблица трассировки требований в общем отчете`
- `fix(uml): исправлены условия ветвления alt в диаграмме корзины UC-05`
- `style: форматирование таблиц и обновление отчета Word перед сдачей`

Запрещаются неинформативные сообщения вида *«update»*, *«fix»*, *«правки»*, *«123»*.

---

## 3. Процедура внесения изменений и Pull Request (Merge Request)

1. **Создание ветки:**
   ```bash
   git switch main
   git pull --ff-only
   git switch -c docs/uc-06-order
   ```
2. **Внесение изменений и коммит:**
   Изменения вносятся в Markdown-файлы (`docs/README.md`, `docs/md/*`), исходники диаграмм (`docs/draw/*.puml`) и изображения (`docs/img/*.png`).
   ```bash
   git add docs/
   git commit -m "docs: добавлено описание и диаграмма UC-06"
   git push -u origin docs/uc-06-order
   ```
3. **Открытие Pull Request (PR):**
   В описании PR указываются:
   - Цель изменений;
   - Связанные требования (ФТ) и варианты использования (UC);
   - Список затронутых файлов;
   - Способ проверки.
4. **Взаимное рецензирование (Peer Review):**
   - Другой участник команды обязан просмотреть diff, проверить соответствие требованиям и оставить содержательный отзыв (Approve или Request Changes).
   - Автор не может сам одобрить и слить свой собственный PR.
5. **Слияние (Merge):**
   После получения подтверждения выполняется слияние средствами платформы (GitHub/GitLab), после чего локальная ветка `main` обновляется (`git pull --ff-only`).

---

## 4. Синхронизация форматов (Правило актуальности Markdown и Word)

- Основным источником истины (Single Source of Truth) является формат **Markdown** (`docs/README.md`, `docs/md/*`). Все изменения вносятся в первую очередь в него.
- Файлы **Word** (`docs/report.docx`, `docs/doc/*`) формируются и экспортируются из согласованного Markdown перед каждой контрольной точкой или сдачей.
- Исходный текст диаграммы (`.puml` / `.drawio`) и отрисованное изображение (`.png` / `.svg`) всегда обновляются синхронно в рамках одного коммита.
- Ответственные за подготовку Word-версий:
  - Общий отчет `docs/report.docx`: Мурзаковский Д.
  - Индивидуальные отчеты: каждый участник самостоятельно для своего документа в `docs/doc/`.
